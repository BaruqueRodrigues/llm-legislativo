## Arquivos alterados e interfaces

- `src/legislm/evaluation/metrics.py`: `byte_nll_v1` seleciona por padrão `K=min(512, context_length-1)`; rejeita K fora do limite, texto sem round-trip exato, emissão de PAD/BOS/EOS como texto e segmento que exceda o contexto. Retorna hash determinístico dos IDs e hashes dos textos avaliados, junto de K e contexto. BOS é resolvido pelo tokenizer.
- `src/legislm/evaluation/evaluator.py`: exclui posições com `attention_mask=False` mesmo se o produtor do lote não tiver preenchido o alvo com `-100`; mantém perda somada dividida pelo total de alvos válidos e distingue EOS/texto.
- `src/legislm/evaluation/cli.py`: resolve `--run-id` pelo `latest.json` do `RUN_ROOT` no layout `RUN_ROOT/checkpoints/CHECKPOINT_ID`, sem aceitar ponteiro de outra run; valida a compatibilidade do vocabulário; exige os caminhos declarados sem cair em fixtures; interrompe execução com split vazio ou erro de avaliação; não suprime erro de byte NLL. Por padrão, grava JSON em `RUN_ROOT/evaluation/` e registra proveniência do split e hash do tokenizer. Gerações registram hashes do manifesto de checkpoint, tokenizer, prompts e configuração de geração.
- `src/legislm/evaluation/generator.py`: inclui os hashes de proveniência opcionais no registro JSON da geração.
- `tests/evaluation/test_cli.py`, `tests/evaluation/test_metrics_byte_nll.py`: ampliam os checks de falha explícita, limite de K/contexto, identidade entre granularidades e soma manual da NLL.

Comandos mantidos pela interface:

```bash
python -m legislm.evaluation.cli evaluate --run-id RUN_ID --split validation
python -m legislm.evaluation.cli generate --run-id RUN_ID --prompts configs/evaluation/prompts.json
```

Os dois subcomandos agora gravam no diretório persistente da run se `--output-json`/`--output-file` não for fornecido. Para uma execução científica, usar somente uma release e um checkpoint identificados; não avaliar fixtures como resultado do modelo.
